# How Sparky's Snap Lab was built (and how to add your own projects)

Sparky's Snap Lab is a small follow-along app for kids aged 5 and up. Each project is a
"movie" of snaps: one piece (or a small group) pops onto the board per step, Sparky the dog
says one short sentence in a speech bubble. Before step one a "Things you need" screen lists
every piece and how many. A kid can tap any piece on the board (not wires) to read what it is,
why it is used and how to use it. On the last step the circuit "comes alive": lamps glow, fans
spin, speakers sing.

## Four deployable units

The app is split so that a small change ships on its own, without rebuilding or
redeploying everything else:

| Unit | Folder | What it holds | Changes when | Deploy |
|------|--------|---------------|--------------|--------|
| App shell | `src/`, `public/`, built to `dist/` | React code, styles, icons, service worker | the UI changes | `npm run build`, upload `dist/` |
| Content | `services/content/` | `projects.json`, `parts.json` | a project or piece text changes | upload the folder |
| Voice | `services/voice/` | one `.m4a` clip per sentence, `lips.json` lip-sync tracks | a sentence changes (run `npm run voice`) | upload the folder |
| Sparky | `services/sparky/` | `sparky-svg.svg`, the mascot artwork | the drawing changes | upload the folder |

The app shell fetches the other three at runtime from `/content`, `/voice` and `/sparky` on
its own host by default. To host them elsewhere, set these at build time:

```bash
VITE_CONTENT_URL=https://content.example.com VITE_VOICE_URL=https://voice.example.com VITE_SPARKY_URL=https://sparky.example.com npm run build
```

The other hosts must send `Access-Control-Allow-Origin` for the app's origin. The service
worker precaches only the app shell and caches the services as they are used
(stale-while-revalidate), so a content, voice or artwork deploy reaches installed apps the
next time they open, with no app release.

For a single host, `npm run bundle` builds the shell and copies the three service folders
into `dist/`.

## Run it

```bash
npm install
npm run dev        # http://localhost:5173 (services are served from services/ in dev)
npm test           # checks the content service (see below)
npm run voice      # renders clips for new sentences and rebuilds lips.json (needs ffmpeg)
npm run build      # app shell only -> dist/
npm run bundle     # app shell plus the three services -> dist/, for one host
```

## What is in the box

| File | What it does |
|------|--------------|
| `services/content/projects.json` | The 25 projects. Pure data: where each piece goes and what Sparky says. **Most new work happens here.** |

| `services/voice/` | Sparky's voice clips and `lips.json`. Generated by `scripts/voice.mjs`; do not edit by hand. |
| `services/sparky/sparky-svg.svg` | Sparky. An SVG with its own idle animations and a `.mouth` group that opens with `--mouth`. |

| `src/Board.jsx` | Draws the board as an SVG: a 10 x 7 grid of posts and the pieces placed so far. |
| `src/voice.js` | Plays clips in order, drives `--mouth` from `lips.json`, falls back to the browser voice. |
| `src/services.js` | The three service URLs. |
| `src/shamallya/` | Components vendored from the ShaMallya design system (see below). |
| `src/styles.css` | The playful parts the library does not cover yet: board, project cards, dialog boxes. |
| `scripts/check.mjs` | `npm test`: refuses typos, unknown pieces and pieces that hang off the board. |
| `scripts/voice.mjs` | `npm run voice`: renders clips with Kokoro-82M and computes the lip-sync tracks. |
| `vite.config.js` | Vite, React, PWA, the `@` alias, and the dev-only middleware that serves `services/`. |
| `sparky-snap-lab-components-request.md` | What the app needs from the ShaMallya component library. |

## The board is a map

The board has 10 columns (x = 0 to 9) and 7 rows (y = 0 to 6). A piece is placed by the
post its **first** snap sits on. A 2-snap piece at `{ "x": 3, "y": 1 }` covers posts (3,1) and (4,1).
Add `"v": true` to stand it up: it then covers (3,1) and (3,2).

Every project puts the battery at `{ "p": "B1", "x": 1, "y": 1, "flip": true }`, so the red + is
always post (3,1) and the − is always post (1,1). Keep that habit; it makes projects easy to compare.

Pieces stack like real snap kits: a wire may start on a post that another piece already uses.
The app draws wires thin and on top so the piece underneath stays visible.

## Anatomy of a project (in `services/content/projects.json`)

```json
{
  "id": 26,
  "title": "Night Light",
  "emoji": "🌙",
  "level": 2,
  "steps": [
    { "add": [{ "p": "B1", "x": 1, "y": 1, "flip": true }], "say": "Snap the battery here. The red + goes on the RIGHT." },
    { "add": [{ "p": "S1", "x": 3, "y": 1 }], "say": "Snap the slide switch next to the battery." },
    { "add": [{ "p": "W2", "x": 4, "y": 1 }, { "p": "W3", "x": 5, "y": 1, "v": true }], "say": "Two wires turn the corner." },
    { "add": [{ "p": "L1", "x": 3, "y": 3 }, { "p": "W2", "x": 4, "y": 3 }], "say": "Lamp and a wire." },
    { "add": [{ "p": "W3", "x": 1, "y": 3 }, { "p": "W3", "x": 1, "y": 1, "v": true }], "say": "Close the loop with two more wires." },
    { "go": true, "say": "Slide ON. It glows! Slide OFF when you are done." }
  ]
}
```

`id` is the next free number, `level` is no longer shown (the tag is worked out from the pieces, see below), the last step has `go: true`
and no `add`. Rules the checker enforces (`npm test`): exactly 25 projects with unique ids
(bump the number in `scripts/check.mjs` when you add one), every step has `say`, every `p`
exists in `parts.json`, every piece fits on the board, the last step is `go`.

Then run `npm run voice` so Sparky can read the new sentences, and deploy `services/content`
and `services/voice`. No app build needed.

### A piece

| Key | Meaning |
|-----|---------|
| `p` | key in `parts.json` (`"L1"`, `"W3"`, `"Q2"`...) |
| `x`, `y` | post of the first snap |
| `v` | `true` for vertical (standing up) |
| `flip` | `true` to put the + mark on the far end instead of the first post (battery, LED, capacitor) |

## Writing for a 5-year-old

1. **One action per step.** "Snap the lamp here." Group only wires, never two real parts.
2. **Short words, short sentences.** Under 15 words. Read it out loud; the app will too.
3. **Say where, not just what.** "on the RIGHT", "going down", "next to the battery".
4. **Give a picture for every idea.** Battery = pump. Wire = road. Switch = gate.
   Resistor = speed bump. Capacitor = bucket. Transistor = magic helper.
5. **End with a thing to try.** "Cover the sensor with your hand." Kids learn by poking.
6. **Safety in the sentence that needs it.** Fan projects say "keep fingers away" on the fan step.
7. **No numbers or units.** "100 ohms" means nothing at 5. "Speed bump" does.

## Adding a new piece (in `services/content/parts.json`)

```json
"M2": { "id": "M2", "name": "Meter", "emoji": "🧭", "len": 2, "color": "#adb5bd",
  "what": "A meter shows how much electricity is flowing.",
  "why": "It lets you SEE the push, like a speedometer.",
  "how": "Snap it in the loop. The needle swings when electricity goes through." }
```

| Key | Meaning |
|-----|---------|
| `id` | letters printed on the real piece |
| `len` | snaps long (horizontal) |
| `tall` | snaps tall, for big chips (default 1) |
| `plus` | `true` if it has a + side |
| `pins` | for chips: `{ "LETTER": [col, row] }` so the letters show on the right corners |
| `on` | how it comes alive on the last step: `"glow"`, `"spin"` or `"music"` |
| `onColor` | glow color |
| `what` / `why` / `how` | the three lines the kid hears the first time the piece appears |

The Meet-the-Pieces page and the Things you need screen come from this entry automatically.

## Sparky's voice and lip-sync

Browser speech sounds robotic, and the small neural voices that sound good are 60 to 90 MB
models. A 5-year-old's tablet should not download that. So the model runs once, on the
developer's computer, and the voice service ships tiny audio clips instead:

1. `npm run voice` collects every step's `say` sentence.
2. Sentences with no clip yet are rendered with **Kokoro-82M** (the `kokoro-js` package,
   `af_heart` voice, speed 0.95). The first run downloads the ~90 MB model into the npm
   cache; later runs are instant for sentences that already have a clip.
3. `ffmpeg` squeezes each clip to mono AAC and normalizes it to a calm -20.5 LUFS
   (about 20 KB per sentence, 152 clips).
4. The script then reads every clip's loudness in 40 ms windows and writes `lips.json`:
   one digit 0 to 9 per window per clip, about 23 KB in all. Vowels are loud (mouth open),
   consonants and pauses are quiet (mouth closed), so the mouth follows the speech.
5. Clips are named `p<project>-<step>.m4a`.

There is no language model that does 2-D lip-sync. The usual tool for cartoon mouths is
Rhubarb Lip Sync (rule-based, outputs mouth shapes A to H from the audio); it would slot
into step 4 if mouth *shapes* are ever wanted instead of open/closed. Loudness was chosen
because it needs nothing but ffmpeg and gives exact timing.

In the app, `say()` in `src/voice.js` plays the step clip and publishes the mouth level (0 to 1)
every 40 ms from the clip's current time; `useMouth()` hands it to the Mascot, which sets
`--mouth` on Sparky's box. His `.mouth` group scales with that property. If a clip is missing (you added a project and
forgot `npm run voice`), the browser voice reads the text and the mouth flaps randomly.
Sparky speaks only in Play mode: Pause stops him, and Back or Next by hand are silent.
In Play mode the next step starts 0.8 s after the voice finishes; with the voice muted,
Sparky is hidden and Play uses a 4.5 s timer.

If you change a sentence, delete its clip and run `npm run voice` again. To change the
voice, edit `voice:` in `scripts/voice.mjs` (Kokoro ships about 50 voices) and delete the
clips.

## Sparky's artwork

`services/sparky/sparky-svg.svg` is fetched at runtime and inlined, so the drawing can be
replaced without an app release. The contract for a new drawing:

- its own idle animations in an embedded `<style>` (wag, blink, breathe) are fine;
- a group with class `mouth` whose `transform: scaleY(var(--mouth, 0))` opens the mouth;
- `width="100%" height="100%"`; the app sizes it (150 px desktop, 100 px phone).

## ShaMallya design system

Everything visible except the board comes from the ShaMallya component library
(`src/shamallya/components/`, vendored 2026-11-11 from `ShaMallya Components`, with
`@shamallya-ui/tokens` 0.6.0, Tailwind 3.4, `src/styles/shamallya-mapping.css` and
`tailwind.shamallya.ts`): Button (`size="kid"`), IconButton, IconToggle (mute), BackLink,
PushedHeader, ScreenHeader, SectionHeading, Caption, SpeechBubble, Mascot (loads
`services/sparky/sparky-svg.svg`, takes the mouth level as a prop), BottomActionBar,
TileCard, GlossaryCard, SafetyNotice, ProgressDots and the announce live region. To update
them, copy the changed files over from the library. Only the snap board, the "Things you
need" tiles and a few layout rules live in `src/styles.css`. The brand theme (R9) is still
with Token Forge, so the app uses the default light theme. The root sets `data-theme="light"`
and `data-density="comfortable"`.

## Screens

- `#` Home: project tiles, Meet the Pieces, Safety Rules.
- `#parts` Meet the Pieces: a card for every piece.
- `#p/7` Things you need: the pieces and counts for project 7, computed from its steps. Tap a
  piece and Sparky explains it in his bubble (silent; the board pieces are not tappable).
- `#p/7/go` The project. Tap Sparky for a hop, spin or wiggle, a bark and a word.

Each project tile carries a difficulty tag worked out from the number of pieces, wires not
counted (`level()` in `src/App.jsx`): up to 3 Starter, 4 to 7 Explorer, 8 to 14 Builder, 15 or
more Inventor.

## How the "movie" works (for the curious)

- The Project screen keeps one number: the current step `i`.
- Pieces on the board = all `add` lists from step 0 to step `i`, flattened.
- Pieces from step `i` get the `snap` CSS class, which plays the bounce-in animation,
  and a 👆 hand slides to the last one.
- Changing `i` plays a short "click" (Web Audio oscillator, no sound file), announces the
  sentence to assistive technology, and Sparky reads it (see above).
- On the last step `live` is true: parts with `on: "glow"` pulse, `"spin"` rotates the
  emoji, `"music"` bounces a note. The project id is saved to `localStorage` so the home
  tile shows a ⭐.
- The URL hash picks the screen: `#` home, `#parts` glossary, `#p/7` project 7. That gives a
  working back button on phones for free.

## Known simplifications

- Pin positions on the big chips (U1, U2, U3) and the transistor (Q2) are drawn as a tidy
  3 x 2 block. Real parts may put the letters in different corners. The text always says
  "match the letters on your piece", and the Meet dialog repeats it.
- Stacking levels (1-snap spacers) are not modeled. Later pieces simply draw on top.
- Emoji are the only artwork besides Sparky, so the app needs no images and stays tiny.
- Lip-sync is open/closed by loudness, not mouth shapes per sound.
